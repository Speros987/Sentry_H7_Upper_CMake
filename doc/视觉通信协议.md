# 视觉通信协议

本文档根据 `Application/inc/Vision.h`、`Application/src/Vision.c` 和 USB CDC 接收回调整理。

## 1. 通信方式

- 传输通道：USB Device CDC（虚拟串口）。
- 接收入口：`USB_DEVICE/App/usbd_cdc_if.c` 中的 `CDC_Receive_HS()`。
- 接收回调收到数据后调用 `Vision_DataReceive(Buf, *Len)`。
- 发送任务：`OS_VisionCallback()` 周期调用 `Vision_DataTransmit()`，再通过 `CDC_Transmit_HS()` 发送。
- 结构体使用 `__attribute__((packed))`，字段按声明顺序连续排列，不插入对齐填充。
- 代码中没有实现校验和或 CRC；帧尾字段用于基本的帧边界标识。

## 2. 视觉模块发送给底盘（接收帧）

接收帧对应 `VisionReceive`，帧头为 `0xA5`，帧尾字段为结构体最后的 `end_frame`（发送端应填入约定的帧尾值）。

| 顺序 | 字段 | 类型 | 含义 |
|---:|---|---|---|
| 1 | `header` | `uint8_t` | 帧头，必须为 `0xA5` |
| 2 | `tracking` | `uint8_t` | 目标类型：0 无目标，1 装甲板，2 符 |
| 3 | `base_yaw` | `float` | 云台/底盘目标角度，单位：度 |
| 4 | `top_yaw` | `float` | 上云台目标角度，单位：度 |
| 5 | `pitch` | `float` | 目标俯仰角 |
| 6 | `incident_yaw` | `float` | 入射角，单位：弧度 |
| 7 | `distance` | `float` | 两车中心距离 |
| 8 | `armor_radius` | `float` | 装甲板物理半径 |
| 9 | `rune_number` | `uint8_t` | 符编号；变化可触发一次开火 |
| 10 | `force_shoot` | `uint8_t` | 强制开火：0 不开火，1 开火 |
| 11 | `linear_x` | `float` | AI 发送的 X 方向线速度 |
| 12 | `linear_y` | `float` | AI 发送的 Y 方向线速度 |
| 13 | `angular_z` | `float` | 旋转角速度 |
| 14 | `align_yaw` | `float` | 与起伏路段对齐角度 |
| 15 | `rune_yaw` | `float` | 符的角度 |
| 16 | `outpost_yaw` | `float` | 前哨站角度 |
| 17 | `spin_mode` | `uint8_t` | 小陀螺：0 关闭，1 开启 |
| 18 | `sentry_mode` | `uint8_t` | 哨兵模式：1 进攻，2 防守，3 移动 |
| 19 | `armor_mode` | `uint8_t` | 目标模式：0 装甲板，1 前哨，2 符 |
| 20 | `align_mode` | `uint8_t` | 对齐模式：0 不对齐，1 对齐起伏路段 |
| 21 | `energy_activation` | `uint8_t` | 能量机关：0 不激活，1 小符，2 大符 |
| 22 | `buy_life` | `uint8_t` | 是否购买复活：0 否，1 是 |
| 23 | `remote_buy_blood` | `uint8_t` | 远程购买血量次数/控制量 |
| 24 | `remote_buy_bullet` | `uint8_t` | 远程购买弹药次数/控制量 |
| 25 | `buy_projectile` | `uint16_t` | 购买弹药数量 |
| 26 | `end_frame` | `uint8_t` | 帧尾 |

底盘收到数据后，`Vision_DataReceive()` 会在本次 USB 数据中向后扫描 `0xA5`。找到后直接执行：

```c
memcpy(&vision_receive, read_from_usart, sizeof(vision_receive));
```

然后调用 `Vision_ParseData()`。解析结果会更新云台目标、底盘速度、哨兵模式、购买指令和开火逻辑。

## 3. 底盘发送给视觉模块（发送帧）

发送帧对应 `VisionTransmit`，帧头为 `0x5A`，帧尾为 `0xA5`。字段顺序如下：

| 顺序 | 字段 | 类型 | 含义 |
|---:|---|---|---|
| 1 | `header` | `uint8_t` | 帧头，固定 `0x5A` |
| 2 | `detect_color` | `uint8_t` | 目标颜色：0 红，1 蓝 |
| 3 | `mode` | `uint8_t` | 模式：0 装甲板，1 前哨，2 符 |
| 4 | `roll` | `float` | 横滚角，来自 `INS.roll` |
| 5 | `pitch` | `float` | 俯仰角，来自 `INS.pitch` |
| 6 | `top_yaw` | `float` | 上云台角度 |
| 7 | `diff_yaw` | `float` | 大小 yaw 电机之间的角度差 |
| 8 | `diff_pitch` | `float` | pitch 电机位置角度 |
| 9 | `bullet_speed` | `float` | 当前弹速 |
| 10 | `robo_status` | `uint8_t` | 机器人状态；当前代码固定填 `0xFF` |
| 11 | `AI_Judge_data` | `Judge_Data_e` | 比赛状态、血量、弹量、哨兵状态等裁判系统数据 |
| 12 | `see_enemy` | `uint8_t` | 目标状态，取 `vision.tracking` |
| 13 | `end_frame` | `uint8_t` | 帧尾，固定 `0xA5` |

发送数据由以下代码完成：

```c
CDC_Transmit_HS((uint8_t*)&vision_transmit, sizeof(vision_transmit));
```

## 4. 接收回调与缓冲区关系

USB CDC 接收到数据后，协议栈把数据放入 `UserRxBufferHS`，再调用：

```c
CDC_Receive_HS(uint8_t *Buf, uint32_t *Len)
```

回调内部将 `Buf` 和实际长度 `*Len` 交给视觉协议解析。处理完成后重新调用 `USBD_CDC_ReceivePacket()`，使 USB CDC 继续接收下一包。

## 5. 当前协议实现的注意事项

1. 接收端只扫描帧头并检查 `length == 0`，没有检查 `length >= sizeof(VisionReceive)`；USB 分包或半帧到达时可能发生越界读取。
2. 接收端没有验证 `end_frame`，也没有校验和/CRC，帧内容损坏时可能被当作有效数据解析。
3. `float`、整数的字节序依赖双方 CPU 的实现；当前协议默认双方使用相同的字节序和浮点格式。
4. `CDC_Receive_HS()` 每次回调处理一包 USB 数据；如果一个完整视觉帧跨越多个 USB 包，当前代码没有组帧缓存机制。

## 6. 给上位机脚本使用的精确帧定义

### 6.1 通用规则

- 所有字段按表格顺序连续排列，偏移量从 0 开始。
- `uint8_t` 占 1 字节，`uint16_t` 占 2 字节，`uint32_t` 占 4 字节，`float` 占 4 字节。
- STM32 与常见 PC 均使用 IEEE-754 单精度浮点数；当前工程默认使用小端字节序（little-endian）。Python 可使用 `struct.unpack('<...')`。
- 结构体是 packed 布局，不能按 C 编译器默认对齐方式插入填充字节。
- 接收帧 `VisionReceive` 固定长度为 **63 字节**。
- 发送帧 `VisionTransmit` 固定长度为 **49 字节**。

### 6.2 上位机 → STM32：VisionReceive，63 字节

| 偏移 | 长度 | 格式 | 字段 |
|---:|---:|---|---|
| 0 | 1 | `B` | `header`，固定 `0xA5` |
| 1 | 1 | `B` | `tracking` |
| 2 | 4 | `f` | `base_yaw` |
| 6 | 4 | `f` | `top_yaw` |
| 10 | 4 | `f` | `pitch` |
| 14 | 4 | `f` | `incident_yaw`，弧度 |
| 18 | 4 | `f` | `distance` |
| 22 | 4 | `f` | `armor_radius` |
| 26 | 1 | `B` | `rune_number` |
| 27 | 1 | `B` | `force_shoot` |
| 28 | 4 | `f` | `linear_x` |
| 32 | 4 | `f` | `linear_y` |
| 36 | 4 | `f` | `angular_z` |
| 40 | 4 | `f` | `align_yaw` |
| 44 | 4 | `f` | `rune_yaw` |
| 48 | 4 | `f` | `outpost_yaw` |
| 52 | 1 | `B` | `spin_mode` |
| 53 | 1 | `B` | `sentry_mode` |
| 54 | 1 | `B` | `armor_mode` |
| 55 | 1 | `B` | `align_mode` |
| 56 | 1 | `B` | `energy_activation` |
| 57 | 1 | `B` | `buy_life` |
| 58 | 1 | `B` | `remote_buy_blood` |
| 59 | 1 | `B` | `remote_buy_bullet` |
| 60 | 2 | `H` | `buy_projectile` |
| 62 | 1 | `B` | `end_frame` |

Python 解析格式：

```python
RX_FORMAT = '<BB6fBB6f8BH B'.replace(' ', '')
# 等价于：<BB6fBB6f8BHB
assert struct.calcsize(RX_FORMAT) == 63
```

发送帧的 `end_frame` 需填入上位机约定的帧尾。当前底盘代码只检查帧头 `0xA5`，不检查帧尾。

### 6.3 STM32 → 上位机：VisionTransmit，49 字节

| 偏移 | 长度 | 格式 | 字段 |
|---:|---:|---|---|

| 2 | 1 | `B` | `mode`，0 装甲板，1 前哨，2 符 |

| 29 | 2 | `H` | `AI_Judge_data.remain_time`，秒 |

Python 解析格式：

```python

# 等价于：<3B6fBB3HIH2B2H2B
assert struct.calcsize(TX_FORMAT) == 49
```

### 6.4 Python 打包示例

```python
import struct

frame = struct.pack(
    '<BB6fBB6f8BHB',
    0xA5, tracking,
    base_yaw, top_yaw, pitch, incident_yaw, distance, armor_radius,
    rune_number, force_shoot,
    linear_x, linear_y, angular_z, align_yaw, rune_yaw, outpost_yaw,
    spin_mode, sentry_mode, armor_mode, align_mode,
    energy_activation, buy_life, remote_buy_blood, remote_buy_bullet,
    buy_projectile, 0xA5,
)
assert len(frame) == 63
```

发送时应保证一次写入完整 63 字节帧，并在发送频率上留出 USB CDC 处理时间。接收 STM32 的 49 字节帧时，先检查 `data[0] == 0x5A`，再按上表使用 little-endian 解包。
